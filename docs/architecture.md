# 教材確認版の構成

## 修正する場所

|変更内容|場所|
|---|---|
|コース名・順序・到達項目|`content/courses/pc-foundations/course.json`|
|各レッスンの解説・具体例・図・実践課題|`content/courses/pc-foundations/lessons/`|
|問題・選択肢・正答・補足|`content/courses/pc-foundations/assessments/`|
|ページとURL|`src/app/`|
|解説の共通部品|`src/components/content/`|
|問題と結果の表示部品|`src/components/assessment/`|
|メニューと文字サイズ|`src/components/layout/`|
|配色・文字サイズの共通設定|`src/styles/tokens.css`|
|レイアウト|`src/app/globals.css`|
|出題・採点・進級ルール|`src/domain/assessment.ts`|
|データの保存先|`src/server/repositories/`|

上記の `pc-foundations` はコースIDです。新コースは `file-data` フォルダーに同じ構成で保存しています。

`web-foundations` はWeb・HTMLの基礎です。到達項目の `codeExample` はコードをエスケープした文字として表示し、`demo: "box-model"` は共通の余白比較部品を表示します。教材JSONから任意のHTMLやスクリプトを実行しません。比較の操作は採点や進級に影響せず、理解の確認はミニテストで行います。コース一覧とホームは同じ `CourseCards` を利用します。

教材と設問は到達項目IDで関連付けます。コースを追加する際は `src/lib/course-catalog.ts` に公開用のコース定義を登録します。共通ルート `/courses/[courseId]/lessons/[slug]` が各ページを表示するため、コースごとの画面の複製は不要です。レッスンのslug・ID・到達項目ID・問題IDは全コースで一意にします。APIと既存記録はこの一意性を利用し、テストで重複を検出します。

新しいレッスンを加える際は、コース一覧・解説・設問のIDを揃えます。既存の学習記録と区別する必要のある変更ではバージョンも更新します。旧HTMLプレビューは別実装であり、自動同期されません。

## 学習の流れ

解説から確認問題へ進むと、サーバーが到達項目ごとに問題を選びます。出題・選択順を保存し、再読み込み時も同じ回答途中の状態へ戻ります。回答は選択ごとに保存、メモは保存ボタンで保存します。

採点後、誤答した項目だけ補足を表示し、次は直前と異なる問題を優先して出題します。ヒント使用と再確認後の正解を記録します。全項目を確認すると次のレッスンが開きます。記録から不正や実際の理解度を断定する機能はありません。

## 保存と本番化

現在はHttpOnly Cookieの匿名IDとローカルJSONを使う、単一プロセス用の確認版です。メール認証・受講権限・講師権限はありません。教材確認モードは誰でも利用できます。画面上の進級制限は有料教材の保護機能ではありません。

Supabase接続時はリポジトリーの実装を置き換え、ユーザーID・RLS・DBトランザクション・設問バージョンの保持を設計します。メールOTP、講師権限、受講権限のサーバー確認は別途必要です。Stripe導入時はWebhookで受講権限を更新し、ブラウザの決済完了画面だけで権限を付与しない構成にします。

サーバー版の公開にはNode.js対応ホスティングが必要です。GitHub Pagesでは `scripts/build-pages.cjs` が作る静的デモを公開します。現行ソースを専用ディレクトリへコピーし、全ルートを事前生成、APIの代わりに `src/demo/api.ts` を利用します。保存はlocalStorage、採点ロジックは共通です。正答も配信するデモであり、認証や不正防止機能とは切り離します。

## 検証

`npm test` は教材の整合性、採点、再出題、進級、保存の競合と失敗時の挙動を確認します。`npm run test:e2e` は製品ビルドを専用ポート3100で起動し、Google Chromeで学習操作・再開・画面表示・APIを検証します。先に `npm run build` を実行してください。

自動アクセシビリティ検査の合格だけで、すべての利用者への使いやすさを保証するものではありません。実際の受講者による読みやすさ・理解の確認も継続します。

インターネットコースのURL比較は、到達項目に `demo: 'url-parts'` を指定します。説明用URLを部品に分けて表示するだけで、外部への通信や採点記録の更新は行いません。
